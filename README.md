# Summer 2027 Internship Scanner

A free-tier-friendly daily internship scanner for a mechanical engineering student targeting **Summer 2027** mechanical, robotics, manufacturing, and related engineering internships in the **NYC metro area or fully remote**.

It stores matches in SQLite, generates a searchable website, optionally syncs Google Sheets, and optionally emails a daily digest. GitHub Actions runs it automatically once per day near **7 AM America/New_York**.

## What the website does

`docs/index.html` is a static GitHub Pages dashboard. It supports search, sorting, preferred-vs-other filtering, "found today," links to postings, and a **Download CSV** button. No web server or paid hosting is needed.

## Important source note

This project does **not** bypass CAPTCHAs, logins, robots restrictions, or anti-bot systems. Company pages are best-effort and isolated so one changing site cannot break the scan. Indeed does not have a universally available anonymous public feed assumed by this project, so the Indeed adapter intentionally does not scrape protected pages; Google search may still discover Indeed listings. Add public Summer 2027 GitHub lists to `config/config.yaml` as they appear.

Google API products and quotas can change. The scanner works without Google Custom Search credentials, but then Google results are skipped. The configuration rotates only a subset of queries each day to conserve quota.

## Step 1 — Upload this project to GitHub

You already created a repository. Download the ZIP from ChatGPT, unzip it on your computer, then open your GitHub repository and choose **Add file → Upload files**. Drag **the contents inside the `internship-scanner` folder** into GitHub (not the outer folder itself), then commit the upload.

Make sure GitHub shows files such as `README.md`, `run.py`, `config/`, `scanner/`, `docs/`, and `.github/` at the repository root.

## Step 2 — Enable the website

1. In the repository, open **Settings → Pages**.
2. Under **Build and deployment**, choose **Deploy from a branch**.
3. Select your default branch (normally `main`) and the `/docs` folder.
4. Click **Save**.
5. GitHub will display your Pages URL after deployment.

The initial page is generated by the first scanner run. The included project also has a local placeholder generated during packaging.

## Step 3 — GitHub Actions permissions

Open **Settings → Actions → General**. Under **Workflow permissions**, choose **Read and write permissions**, then save. The workflow needs this so it can commit the updated `internships.db` and `docs/index.html`.

## Step 4 — Secrets

Open **Settings → Secrets and variables → Actions → New repository secret**. The supported names are:

- `GOOGLE_API_KEY` — Google Custom Search JSON API key (optional)
- `GOOGLE_CSE_ID` — Programmable Search Engine ID (optional)
- `GOOGLE_SERVICE_ACCOUNT_JSON` — entire service-account JSON document (optional)
- `GOOGLE_SHEET_ID` — ID from the target Google Sheet URL (optional)
- `GMAIL_ADDRESS` — Gmail address sending the digest (optional)
- `GMAIL_APP_PASSWORD` — Google App Password, not your normal password (optional)

You can get the website running **before adding any secrets**. Missing integrations are skipped safely.

## Google search setup

Google's search/API product names, availability, quotas, and pricing can change, so check Google's current terms before enabling it. Create a Programmable Search Engine configured to search the web (or the sites you want), obtain its Search Engine ID, enable the corresponding Custom Search JSON API in a Google Cloud project if available to your account, and create an API key. Save those values as `GOOGLE_CSE_ID` and `GOOGLE_API_KEY`.

If you prefer to avoid this API entirely, leave those secrets unset. GitHub/company sources still run.

## Google Sheets setup

1. Create a Google Cloud project and enable the **Google Sheets API**.
2. Create a service account and a JSON key.
3. Create a Google Sheet and rename its first tab to exactly **Internships**.
4. Share the Sheet with the service account's `client_email` as an **Editor**.
5. Copy the spreadsheet ID from its URL into `GOOGLE_SHEET_ID`.
6. Open the downloaded service-account JSON in a text editor, copy the **entire JSON contents**, and paste that as the value of `GOOGLE_SERVICE_ACCOUNT_JSON`.

Never upload the JSON key file to GitHub.

## Gmail setup

1. Use a Google account with 2-Step Verification enabled.
2. Create a Google **App Password** for this scanner if App Passwords are available for your account.
3. Save your Gmail address as `GMAIL_ADDRESS`.
4. Save the 16-character app password as `GMAIL_APP_PASSWORD`.

The digest is sent from your Gmail account back to the same address. If App Passwords are unavailable on your account, leave these secrets unset; scanning and the website continue to work.

## Step 5 — Run it now

Open **Actions → Daily Internship Scan → Run workflow → Run workflow**. A manual run bypasses the 7 AM time gate. After it finishes, reload the repository and `docs/index.html` / `internships.db` should be updated if data changed.

The schedule contains both possible UTC equivalents of 7 AM New York time and checks `America/New_York` before scanning, which handles daylight-saving changes.

## Editing what it searches

Edit `config/config.yaml`. You can change:

- `search_queries` — 18 rotating Google queries
- `companies` — company career watchlist
- `github_lists` — public crowdsourced Markdown internship lists
- `preferred_keywords`
- accepted NYC/remote location keywords
- rejection keywords

Only six Google queries run per day by default to conserve API quota. Change `google_queries_per_run` if desired.

## Database

`internships.db` contains exactly these columns:

`job_id, title, company, location, deadline, paid, cover_letter_required, source, source_url, date_found, status`

`job_id` is the primary key, so an opportunity already saved is never inserted again. `status=new` means a preferred mechanical/robotics/manufacturing match; `status=other` preserves plausible related engineering opportunities separately.

## Security

Never commit API keys, Gmail passwords, or service-account credentials. Keep them only in GitHub Actions Secrets. The `.gitignore` blocks common local secret files.
